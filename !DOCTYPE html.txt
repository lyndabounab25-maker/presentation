        <h2>Pourquoi Git & GitHub ?</h2>
        <ul>
          <li><strong>Le problème classique :</strong> des dossiers avec <code>projet_v1</code>, <code>projet_final</code>, <code>projet_v2_corrige</code>.</li>
          <li><strong>Le risque :</strong> pertes de code, écrasements involontaires, travail à plusieurs difficile.</li>
          <li><strong>La solution :</strong> un historique rigoureux, chaque changement est tracé et réversible.</li>
        </ul>
      </section>

      <!-- Slide 3 : Git vs GitHub -->
      <section>
        <h2>Git vs GitHub : la distinction</h2>
        <div class="grid">
          <div class="box">
            <h3 style="color:#58a6ff;">Git</h3>
            <p><strong>L'outil local (moteur)</strong></p>
            <ul>
              <li>Logiciel libre installé sur la machine</li>
              <li>Enregistre l'historique des modifications</li>
              <li>Fonctionne hors-ligne</li>
            </ul>
          </div>
          <div class="box">
            <h3 style="color:#58a6ff;">GitHub</h3>
            <p><strong>Le service distant (cloud)</strong></p>
            <ul>
              <li>Plateforme web hébergeant les dépôts Git</li>
              <li>Interface graphique et partage</li>
              <li>Fonctionnalités : Issues, Pull Requests, Pages</li>
            </ul>
          </div>
        </div>
      </section>

      <!-- Slide 4 : Notions clés -->
      <section>
        <h2>Le vocabulaire indispensable</h2>
        <ul>
          <li><strong>Repository (Dépôt) :</strong> dossier central du projet contenant fichiers et historique.</li>
          <li><strong>Commit :</strong> capture instantanée (point de sauvegarde) du code validé.</li>
          <li><strong>Branch (Branche) :</strong> ligne de travail parallèle pour tester sans casser la branche principale (<code>main</code>).</li>
          <li><strong>Pull Request :</strong> proposition de fusionner une branche après vérification.</li>
        </ul>
      </section>

      <!-- Slide 5 : Cas d'usage Infrastructure / Réseau -->
      <section>
        <h2>Utilité en Systèmes & Réseaux</h2>
        <ul>
          <li><strong>Traçabilité :</strong> versionner des scripts (Bash, PowerShell, Python).</li>
          <li><strong>Documentation :</strong> hébergement des documentations techniques (fichiers Markdown).</li>
          <li><strong>GitHub Pages :</strong> déploiement gratuit de sites et portfolios en HTTPS.</li>
        </ul>
      </section>
